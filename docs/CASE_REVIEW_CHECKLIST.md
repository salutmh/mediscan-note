# 케이스 육안 검수 체크리스트

> 새 케이스를 서비스에 올리기 전, **사람이 오버레이 시트를 보고** 통과·반려를 정하는 절차다.
>
> 관련 문서: 파이프라인은 `backend/README.md`, 콘텐츠 원칙은 `docs/CONTENT_GUIDELINES.md`.

---

## 0. 이 문서가 있는 이유

`CONTENT_GUIDELINES.md` 는 "육안 검수를 건너뛰지 않는다"고만 적어두고,
**무엇을 보고 통과·반려를 정하는지**는 적어두지 않았다. 기준이 없으면 검수는 형식만 남는다.

여기서 하는 일은 하나다: **이 GT 마스크를 학습자의 채점 기준으로 써도 되는가.**
GT 가 틀린 채로 올라가면 학습자는 **틀린 기준으로 평가받는다.** 되돌릴 방법은 케이스를
내리는 것뿐이고, 그 전에 쌓인 제출 이력은 의미가 없어진다.

---

## 1. 세 종류의 확인을 섞지 않는다

| 누가 | 무엇을 확인하나 | 판단 근거 |
|---|---|---|
| **기계 (이미 끝남)** | 볼륨·마스크 shape 일치, GT voxel 수, 병변 slice 범위, 대표 slice, 편측성 계산 | `export_meta.json` |
| **사람 (이 문서)** | 그림이 메타데이터와 맞는가, 명백히 어긋난 곳이 없는가 | 오버레이 시트 |
| **전문가만** | 이 마스크가 **의학적으로 옳은 병변 범위인가**, 난이도는 어떤가 | 영상의학 지식 |

**2번은 의학 지식 없이도 할 수 있다** — "메타데이터가 말하는 것과 그림이 같은가"를 보는 것이다.
**3번은 대신할 수 없다.** 아래 2절을 전부 통과해도 그것은 "파이프라인이 제대로 돌았다"는 뜻이지
"의학적으로 옳다"는 뜻이 아니다. 3절을 반드시 함께 읽는다.

---

## 2. 사람이 그림으로 확인하는 것 (의학 지식 불필요)

오버레이 시트(`data/<검수폴더>/<CASE_ID>/review.png`)를 연다.
윗줄은 병변 시작·대표·끝 slice 전체 뷰, 아랫줄은 같은 slice 의 병변 주변 확대다.

### 2.1 마스크가 영상 위에 얹혀 있는가

- [ ] 빨간 채움(병변)과 노란 외곽선이 **해부학적 구조 위**에 있다
      (배경 검은 공간이나 영상 밖에 떠 있지 않다)
- [ ] 마스크가 **한 덩어리**다. 서로 멀리 떨어진 조각으로 흩어져 있으면 반려하고 원인을 확인한다
      (다발성 병변일 수도 있으므로 **자동으로 지우지 말고** 3절로 넘긴다)
- [ ] 확대 뷰에서 외곽선이 영상의 경계와 **어긋나게 밀려 있지 않다**
      (통째로 몇 픽셀 이동해 보이면 좌표계 문제다 — 반드시 반려)

### 2.2 메타데이터와 그림이 일치하는가

`export_meta.json` 을 열어 세 값을 그림과 대조한다.

- [ ] `representative_slice` 로 표시된 가운데 칸에 병변이 **가장 크게** 보인다
- [ ] `laterality` 가 `left` 면 그림에서도 병변이 **환자 왼쪽**에 있다
      (영상은 보통 좌우가 뒤집혀 보인다 — `laterality.agree: true` 이고
      `laterality_by_fov_center` 와 `laterality_by_head_center` 가 같은지 함께 확인한다.
      두 값이 다르면 계산이 확신하지 못한 것이므로 반려한다)
- [ ] `lesion_slice_count` 가 1 이면 특히 주의해서 본다
      (한 장에만 있는 마스크는 잘못 그린 것일 가능성이 있다 — 3절로 넘긴다)

### 2.3 ROI 선택이 맞는가

- [ ] `chosen_roi` 가 종양 ROI 다 (`TV` / `AN` / `GTV` 등).
      `Cochlea`(달팽이관), `*Skull`(두개골) 같은 **다른 구조가 선택됐으면 반드시 반려**한다
- [ ] `roi_selected_by` 가 `keyword` 가 아니면 사람이 지정한 것이다 — 왜 그랬는지 기록을 확인한다

> ROI 후보가 0개거나 2개 이상이면 export 가 **중단**되므로 여기까지 오지 않는다.
> 그래도 확인하는 이유: 키워드가 우연히 하나만 맞은 경우가 있을 수 있다.

### 2.4 학습 자료로 쓸 만한가

- [ ] 영상이 **판독 가능한 품질**이다 (심한 아티팩트·잘림으로 병변 주변을 볼 수 없으면 반려)
- [ ] 대표 slice 의 병변이 **너무 작아 화면에서 보이지 않는 수준**은 아니다
      (`representative_area_px` 가 100 미만이면 확대 뷰로 한 번 더 본다.
      작다는 것 자체는 반려 사유가 아니다 — 소형 병변도 학습 대상이다.
      다만 화면에서 식별조차 안 되면 ROI 로 표시할 수 없다)

## 3. 전문가가 아니면 판단할 수 없는 것

아래는 **이 체크리스트로 대신할 수 없다.** 2절을 전부 통과해도 여기가 남는다.

- **이 마스크가 병변의 옳은 범위인가.** 경계를 더 넓게/좁게 잡아야 하는지, 인접 구조가
  포함됐는지는 영상의학 판단이다.
- **다발성으로 보이는 조각이 실제 병변인가, 잡음인가.**
- **`difficulty`(난이도).** 크기·모델 성능은 계산값일 뿐 난이도가 아니다.
  판단이 없으면 **비워 둔다** (`null`). 임의로 채우지 않는다.
- **`case_findings`(케이스별 영상 소견).** 검토자·검토일 없이는 등록하지 않는다
  (`CONTENT_GUIDELINES.md` 4절).

> 전문가 검토 전이라도 2절을 통과한 케이스는 **판독 훈련용으로 등록할 수 있다.**
> 채점 기준은 데이터셋의 전문가 GT(RTSTRUCT)이고, `case_findings` 는 비워 두면 화면에서
> "아직 등록되지 않았습니다"로 정직하게 표시된다.
> 다만 GT 자체의 의학적 타당성 검토는 **BLOCKER-2 로 열려 있다** (`docs/CLAUDE_HANDOFF.md`).

---

## 4. 절대 하지 않는 것

- **GT 를 보기 좋게 고치지 않는다.** 최소 면적 필터·구멍 메우기·스무딩 전부 금지다.
  이상해 보이면 **고치는 것이 아니라 반려**한다.
- **"대충 맞아 보이니 통과"로 넘기지 않는다.** 애매하면 반려하고 3절로 올린다.
  케이스 하나를 더 넣는 것보다 틀린 기준을 넣지 않는 것이 중요하다.
- **검수 기록 없이 등록하지 않는다.** 누가 언제 봤는지 모르면 나중에 되짚을 수 없다.

---

## 5. 기록 양식

케이스마다 아래를 남긴다 (`data/<검수폴더>/review_log.md` 등, **커밋하지 않는다** —
`data/` 는 gitignore 다).

```
CASE_ID: VS-SEG-018
검수자:
검수일:
결과: 통과 | 반려 | 보류(전문가 확인 필요)
2절 확인: 2.1 [ ] 2.2 [ ] 2.3 [ ] 2.4 [ ]
비고:
```

- **통과** → 3단계(자산 생성) → 4단계(등록)로 진행
- **반려** → 등록하지 않는다. 사유를 남긴다
- **보류** → 등록하지 않고 전문가 확인을 기다린다

## 6. 실행 순서

```bash
cd backend
VENV="<학습 venv>/Scripts/python.exe"     # pydicom/rt_utils 가 필요하다

# 1) export (이미 끝났다면 건너뛴다)
"$VENV" -m scripts.export_vs_seg_npy \
    --data-root <DICOM루트> --out data/expansion_export --cases VS-SEG-018 ...

# 2) 검수 시트 생성 — DB 에 아무것도 등록하지 않는다
python -m scripts.make_review_overlays \
    --export-root data/expansion_export --out data/expansion_review

# 3) 사람이 data/expansion_review/*/review.png 를 보고 이 문서로 판단한다
#    통과한 케이스만 아래로 넘어간다

# 4) 자산 생성 (통과 케이스만)
python -m scripts.build_vs_seg_case_assets \
    --export-root data/expansion_export --out data/expansion_cases --margin 3

# 5) 등록
python -m scripts.import_cases data/expansion_cases/manifest.json

# 6) 등록 후 점검 (Dice=1.0 자가점검 포함)
python -m scripts.verify_cases
```

> 3단계와 검수 시트는 **같은 표시용 정규화 함수**를 쓴다.
> "승인한 그림 = 올라간 그림"을 보장하기 위해서다.
